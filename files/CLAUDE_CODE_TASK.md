# 작업 지시 — 나경(패철) 기능 추가

Destiny Code 사주 앱에 풍수 나경 기능을 추가한다. 컴포넌트와 계산 라이브러리는 이미 작성되어 있으니, 프로젝트 구조에 맞게 배치하고 연결하는 것이 이 작업의 범위다.

---

## 0. 먼저 파악할 것

코드를 쓰기 전에 아래를 확인하고, 확인 결과를 한 줄씩 보고할 것.

- [ ] App Router인가 Pages Router인가 (`app/` vs `pages/`)
- [ ] `tsconfig.json`의 `paths`에 `@/*` 별칭이 있는가. 없거나 다르면 두 파일의 import 경로를 프로젝트 규칙에 맞게 고칠 것
- [ ] 헤더 내비게이션 컴포넌트의 파일 경로 (명식·오늘의 운세·고전·궁합·공부·저장됨 링크가 있는 곳)
- [ ] 사용자의 생년월일과 성별이 저장되는 자료 구조와 그 위치. 타입 이름과 필드명을 그대로 적을 것
- [ ] 그 생년이 **입춘 보정된 값**인지, 아니면 양력 연도 그대로인지

마지막 항목이 중요하다. 판단이 안 서면 추측하지 말고 물어볼 것.

---

## 1. 파일 배치

제공된 두 파일을 그대로 넣는다. 내용을 임의로 수정하지 않는다.

```
lib/eightMansions.ts       ← 팔택풍수 계산. 순수 함수만 있고 의존성 없음
components/Luopan.tsx      ← 나경 UI. "use client" 필수
```

`lib/`이나 `components/`가 프로젝트에서 다른 이름을 쓰고 있으면 그 관례를 따르고, import 경로를 맞춰 고친다.

---

## 2. 페이지 추가

`app/luopan/page.tsx` (또는 라우터에 맞는 위치)를 만든다.

```tsx
import Luopan from "@/components/Luopan";

export const metadata = {
  title: "나경 · Destiny Code",
  description: "휴대폰 방위 센서로 좌향을 재고 팔택풍수 길흉 방위를 확인합니다.",
};

export default function Page() {
  return (
    <main style={{ padding: "24px 16px" }}>
      <Luopan />
    </main>
  );
}
```

레이아웃 컨테이너나 패딩은 기존 페이지들(`/today`, `/compatibility` 등)과 동일한 방식을 쓴다. 위 `style`은 예시일 뿐이니 프로젝트 관례로 대체할 것.

---

## 3. 내비게이션 연결

헤더 메뉴에 `나경` 항목을 추가한다. 위치는 `궁합`과 `공부` 사이.

모바일 메뉴가 별도로 있으면 양쪽 다 넣는다.

---

## 4. 명식 데이터 연동

저장된 사용자 정보가 있으면 자동으로 본명괘가 잡히도록 넘긴다.

```tsx
<Luopan birthYear={/* 입춘 보정된 연도 */} gender={/* "male" | "female" */} />
```

- 보정된 연도를 이미 갖고 있으면 → `birthYear`로 넘긴다
- 양력 생년월일만 있으면 → `birthDate={new Date(...)}`로 넘긴다. 컴포넌트가 2월 4일 기준으로 근사 보정한다
- **프로젝트에 절기(節氣) 계산이 이미 있으면 반드시 그것을 쓴다.** 근사 보정은 2월 3~5일 출생자에서 틀린다
- 저장된 정보가 없으면 프롭을 생략한다. 컴포넌트가 자체 입력 UI를 띄운다

성별 필드가 `"M" | "F"`나 `0 | 1` 같은 다른 형태면 호출부에서 변환한다. 컴포넌트 타입은 건드리지 않는다.

---

## 5. 손대지 말 것

- `lib/eightMansions.ts`의 계산 로직. 변효법 구현과 본명괘 공식은 검증을 마쳤다. 표로 바꿔 쓰지 말 것
- 팔택파 기준이라는 안내 문구, 공망 경고, 주방 압살 설명. 사용자 오해를 막는 장치다
- `"use client"` 지시어
- 새 의존성 추가. 이 컴포넌트는 React 외에 아무것도 쓰지 않는다

---

## 6. 검증

```bash
npx tsc --noEmit     # strict 통과해야 함
npm run lint
npm run build
```

빌드가 통과하면 배포하고, **실제 안드로이드 기기의 크롬에서** 아래를 확인한다. 데스크톱에서는 센서가 없어 확인이 불가능하다.

- [ ] `센서 켜기`를 누르면 판이 회전하는가
- [ ] 화면 아래 `신호 출처`가 `절대 방위 이벤트` 또는 `OrientationSensor`로 뜨는가
- [ ] `상대 방위`로 뜨면 `여기가 북` 버튼이 나타나는가
- [ ] 북쪽을 향했을 때 판의 `子`가 위쪽 붉은 화살표에 오는가
- [ ] 출생연도와 성별을 넣으면 안쪽 고리에 생기·천의 등이 표시되는가
- [ ] `지금 향을 집 향으로`를 누르면 택괘가 잡히고 배합/불배합이 뜨는가
- [ ] 경계 각도에서 공망 경고가 뜨는가

센서가 안 잡히면 브라우저 주소창 자물쇠 → 사이트 설정 → 모션 센서 허용을 확인한다. Vercel 배포본은 HTTPS라 이 문제는 대개 생기지 않는다.

## 참고 — 컴포넌트가 제공하는 것

| 프롭 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `birthYear` | `number` | — | 입춘 보정된 출생 연도 |
| `birthDate` | `Date` | — | 생년월일. `birthYear`가 있으면 무시 |
| `gender` | `"male" \| "female"` | — | |
| `voidTolerance` | `number` | `3` | 공망 허용 오차(도) |
| `defaultTrueNorth` | `boolean` | `false` | 진북 보정 초기값. 전통 나경은 자북 기준 |
| `className` | `string` | — | |

라이브러리 주요 함수:

- `mingGua(year, gender)` — 본명괘
- `houseGuaFromFacing(deg)` — 향 방위각에서 택괘
- `starFor(기준괘, 방위괘)` — 팔성 판정
- `combinedMansions(본명괘, 택괘)` — 여덟 방위 종합
- `compatibility(본명괘, 택괘)` — 배합택 여부
- `voidCheck(deg, tolerance)` — 공망
- `placementAdvice(본명괘, 택괘)` — 용도별 배치
- `MOUNTAINS` — 24산 테이블. 명식 페이지에서도 재사용 가능
